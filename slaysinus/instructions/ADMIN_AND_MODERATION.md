# Предложения пользователей и вход администратора

На сайте одна общая версия. Посетитель видит опубликованных кандидатов и кнопку «Предложить кандидата». Кнопка «Админ» открывает вход организатора по email и паролю. Панель управления появляется только после проверки аккаунта сервером. Свободного входа в демо-панель нет.

## Обновление уже работающей базы

1. Откройте Supabase → SQL Editor.
2. Выполните `database/slaysinus_moderation_migration.sql` целиком.
3. Затем выполните `database/slaysinus_contact_migration.sql` для необязательного контакта отправителя.
4. Загрузите обновлённое содержимое `site/` на хостинг.

Существующие кандидаты остаются опубликованными. Новые предложения посетителей получают статус «На проверке». Для новой базы используйте `database/slaysinus_supabase_setup.sql`: он уже содержит обновление модерации.

## Создание аккаунта организатора

1. В Supabase откройте Authentication → Users и создайте пользователя с email и паролем организатора.
2. Добавьте его в таблицу администраторов через SQL Editor, заменив email:

```sql
insert into public.admin_users (user_id)
select id from auth.users where email = 'admin@example.com'
on conflict (user_id) do nothing;
```

3. Подключите сайт через кнопку «Онлайн»: Project URL и публичный Publishable / anon key.
4. Нажмите «Админ», введите email и пароль созданного аккаунта.

Пароль задаётся в Supabase, не хранится в HTML или JavaScript сайта. Секретный service_role key в браузер вставлять нельзя. Чтобы все посетители использовали одну базу, заполните публичные `PUBLIC_SUPABASE_URL` и `PUBLIC_SUPABASE_KEY` в `site/assets/app.js` перед загрузкой на хостинг; настройка через кнопку «Онлайн» сохраняется только в текущем браузере.

## Проверка и публикация

Пользователь выбирает одну из существующих десяти категорий, указывает имя, описание и необязательное вложение. После отправки заявка исчезает из формы, но не появляется в публичном голосовании или результатах.

В панели администратора есть две группы: «На проверке» и «Опубликованы». Для каждой записи доступны:

- просмотр фото или видео;
- редактирование имени, описания, категории и вложения;
- публикация или скрытие;
- удаление;
- изменение общего количества голосов от 0 до 1000000.

После изменения категории голоса кандидата сбрасываются, сайт предварительно спрашивает подтверждение. Редактирование имени или описания сохраняет голоса. Обычные новые голоса прибавляются к заданному администратором числу. Сервер хранит корректировку отдельно от голосов посетителей, а изменения счётчиков записывает в `vote_adjustment_log`. Сброс всех голосов обнуляет и обычные голоса, и корректировки.

## Фото и видео

Фото доступны во всех категориях: JPEG, PNG, WebP до 8 МБ. Перед отправкой изображение уменьшается до 1200 px по длинной стороне. Карточки показывают крупное фото, без обрезки.

Видео разрешены только для «Deer’s King», «Deer’s Queen», «Завоз года» и «Мем года». Форматы MP4, WebM и MOV до 20 МБ; для совместимости браузеров предпочтителен MP4 с H.264. Видео показывается со стандартными кнопками плеера, без автоматического запуска. Ограничение категорий проверяется и в браузере, и в базе.

Новые вложения хранятся в закрытом bucket `candidate-media`. Неопубликованные файлы доступны только организатору. После публикации сайт выдаёт временные ссылки на 5 минут. Ранее выданные ссылки могут работать до истечения срока после скрытия кандидата. При удалении кандидата новые ссылки не выдаются; оставшиеся файлы можно удалить в Supabase Storage. Старые фотографии из предыдущего публичного bucket сохраняются для совместимости.

Отправка ограничена пятью заявками в час на браузерный токен. Это мягкое ограничение для премии среди знакомых, не проверка личности. Ошибки отправки могут оставлять незадействованные файлы в закрытом bucket; организатор может периодически чистить их в Storage.

## Локальная версия

Без Supabase предложения сохраняются только в текущем браузере и остаются скрытыми. Общая модерация, пароль организатора, публикация и синхронные голоса требуют подключённой базы. В локальном режиме нет обходного входа в админ-панель.

## Проверки

SQL выполнен в локальном PostgreSQL через PGlite с ролями anon/authenticated и тестовыми схемами Auth/Storage. Проверены повторное выполнение миграции, запрет чтения неопубликованных кандидатов и файлов, запрет прямой публикации и изменения голосов посетителем, разрешение публикации администратору, изменение счётчиков, новое голосование, сброс, удаление, перенос категории и ограничения видео.

В Chrome проверены отправка заявки с фотографией, редактирование, публикация, скрытие, удаление, видео WebM, ограничения категорий и крупные карточки на 360, 768 и 1440 px. После удаления демо-входа дополнительно проверены отказ с неверным паролем, появление панели после успешной авторизации и исчезновение инструментов после выхода с тестовым адаптером SDK. Реальный аккаунт Supabase и HTTP-загрузка в его Storage в этой сессии не использовались.

Документация: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [закрытые bucket](https://supabase.com/docs/guides/storage/buckets/fundamentals).


## Необязательный контакт отправителя

В форму добавлено поле Telegram или другого способа связи, до 200 символов. Оно необязательно. Контакт виден администратору в заявке, сохраняется при редактировании и не отображается в публичной карточке. Для существующей базы после модерации выполните `database/slaysinus_contact_migration.sql`. Для новой базы достаточно обновлённого полного setup SQL. Контакт не входит в публичную выборку базы: доступ организатора осуществляется отдельной серверной функцией с проверкой прав.

## Рабочая версия без демо-режима

Локальный вход admin/admin удалён. Без общей базы сайт показывает только статические разделы; заявки и голосование отключены. Панель организатора доступна только после входа в аккаунт Supabase. Старые локальные тестовые записи не показываются.
